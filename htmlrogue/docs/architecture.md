# 架构与扩展

## 数据流

```text
原生 DOM 交互
  → app.js 适配
  → game.js 校验操作与扣除额度
  → events.js 执行源效果、入队连接、记录事件
  → game.js 判定胜负或奖励
  → render.js 将状态投影成实际 DOM
```

引擎不读取 DOM，也不依赖浏览器，因此可直接用 Node.js 测试。视图不决定伤害、奖励或阶段推进。内容定义不持有 UI 元素。

节点定义是共享元数据；节点实例的 `id / type / level / value / used` 属于单局。连接引用稳定实例 ID，克隆创建新 ID，强化不会改变连接。

状态阶段只有 `combat → reward → ready → combat` 与终态 `won / lost`。公开操作先校验阶段和输入；重复选奖、死后行动、非法连接不会消耗资源或改变状态。

## 事件语义

- 手动按钮每回合一次；checkbox/radio/range 每次有效变化消耗 1 操作点。
- 连接目标暂时只允许按钮，确保「自动点击」含义清楚。后续支持自动切换时，需要显式定义 `toggle / select / setValue` 的事件负载。
- 合成事件不触发 DOM `.click()`，也不占用按钮的手动次数，避免浏览器与游戏事件互相重入。
- 每次手动动作拥有独立的 `visited` 集合，循环和多路径汇聚不会重复执行同一节点。队列另有 20 事件硬上限。
- 敌人生命归零立即停止事件队列，不向下一层泄漏事件。
- 双重回响仅追加源元素效果，不再次传播连接。对于状态元素，状态不会切换两次；这条规则更适合按钮构筑。
- 滑杆 `input` 更新预览，`change` 写入状态并触发连接。键盘每次有效改值也属于一次提交。
- 超频自损发生在敌方行动后，护盾不阻挡自损；击败敌人不再执行该回合反击与自损。

## 添加内容

### 新节点

1. 在 `content/nodes.js` 注册定义，明确控件种类与事件。
2. 在 `createNode` 提供实例初值。
3. 在 `engine/game.js` 的 `act` 中加入输入校验。
4. 在 `engine/events.js` 的 `applyEffect` 实现规则。
5. 在 `ui/node-view.js` 提供真实 HTML 控件。
6. 在 `content/rewards.js` 注册奖励，为新规则添加针对性测试。

目前只有四类控件，保留显式分支便于阅读。内容变多时可将 `applyEffect` 拆成按类型索引的效果注册表，不必提前引入插件框架。

### 新敌人

在 `content/enemies.js` 注册数据；若引入新节奏，补充 `enemyIntent` 和回合初始效果。进度来自同一个目录，最终页面判定使用目录长度。扩展关卡数时还需更新界面中的六层说明与分母。

### 新奖励或全局规则

目录在 `content/rewards.js`。唯一规则设置 `unique: true`，节点奖励自动过滤已拥有类型。变异目标要在引擎侧校验，不只依赖 UI 选项。持续规则放到实际触发时机：回合开始、事件执行、清理完成。

### 布局成为规则

目前节点存储是平面数组。未来可以添加 `parentId / region / order` 等实例字段，再由视图投影为真实父子关系。引擎通过结构数据判断路由，不依赖 CSS 坐标，无需改写事件队列。

## 本版边界

- 无存档、撤销或跨局成长；刷新即重开，重开按钮有确认框防误触。
- 原生 ES Modules 需要静态 HTTP 服务；无打包器、框架、外部字体或网络依赖。
- 种子随机用于可复现测试，暂未提供输入种子的界面。
- 为保持 Demo 易读，各区域在动作后重建，通过稳定控件 ID 恢复焦点。更大规模时可做按区域差量更新。
- 平衡性仍是原型水平，通关测试证明至少一条合法路径可行，不代表所有构筑胜率相同。
- 本地服务器只监听环回地址，供本机预览；上线交给静态托管服务。
